# 成片复审、交付与授权清理

验收依据是本项目的教学目标、素材、出镜策略和发布配置。逐项证明操作、图示、原文及剪辑匹配当前讲解；其他项目的固定时长、镜头编号、章数和 PASS 不构成本项目证据。清晰度需要看实际文字和动作，不能仅靠输出分辨率或“商业级”标签判断。

## 默认复审与修复闭环

这是完整制作和已有成片修订的默认收尾工作，无需用户再次提出“检查一下”。先审核本次实际导出的 MP4，发现有依据的缺陷后修复对应内容，重新导出并检查新文件。审核与修复不能停留在报告或建议中；通过后不为凑固定轮数反复编码。

### 内容与接点检查

- **全量字幕文字校对**：逐段核对剪后口播转写、字幕源、SRT 和实际烧入字幕。重点检查术语、数字、专名、否定、条件、漏字、错字和断句，核对显示起止与实际讲话。课稿只辅助核对教学意图和术语，不把正常口语改成没说过的句子。实际烧入层可用 OCR 辅助定位，但字幕源正确或 OCR 无异常不证明最终像素全部正确。
- **实际语音核实**：结合当前环境真实可用的音频理解、原声回听与时间戳对齐，核查错误 take、制作口令、无效重复和关键解释是否残留或被误删。疑似 ASR 错误、数字、否定条件、语义矛盾和重复句回到实际声音；对同一错误转写再次做文字校对不能算独立语音复核。没有正确重录可用时列待补录，不用改字幕、拼造声音或错配嘴型掩盖原口播错误。
- **逐个编辑接点**：从 cuts/keeps、补拍替代及镜头/章节记录枚举口播删剪点、跨源接点、章节与播片出入，并检查成片开头和结尾。从最终成片检查每个接点前后的完整句子与必要动态，核对词头词尾、承接关系、自然呼吸、音量和底噪变化、嘴型、背景及单帧闪回。相邻几百毫秒波形、静态截图或全片相关性不能单独证明语义衔接自然。
- **音画与可读性**：按下文逐镜检查首、中、末、隐藏恢复边界、关键操作和结果，确认讲解与真实素材一致，字幕、提示词、正文和人物互相避让。异常黑帧、静帧和沉默可自动扫描为候选，但要区分设计留白、稳定图示和实际缺陷，不一律判错或删除。

自动化工具负责其实际覆盖的媒体、时钟、响度、结构等检查；agent 负责完成上述语义与音画核对，并准确说明使用的是工具、模型辅助理解、实际回听还是目视。全量文字校对不等于全量原声试听，少量抽样不等于全课逐帧审看。能力或证据缺失时写明具体待核范围，不虚构已完成的检查。

### 问题修复与放行

每个发现记录成片范围、类别、现象、证据、影响、修复方式及复查结果。会改变意思或破坏跟学的口播/字幕错误、遗漏关键解释、错误 take 残留、缺音、明显不同步、重要内容不可读和断裂衔接，列为必须处理的问题；无关紧要的措辞偏好不作为反复重做的理由。

对证据清楚且在制作授权内的问题直接修复：优先选用真实正确 take、校正字幕及其时码、调整剪口、重新匹配镜头或图层。改口播时同步重算后续字幕、人物、实操和章节；只改字幕或画面时保留仍有效的已认可音轨，避免重复剪辑或降噪。

重新导出后，从新文件复查修改段、前后衔接和受影响的后续时钟，并完成整片技术检查。报告按新文件身份更新，未解决的重大问题保持待修；缺少正确素材或必要核实能力时保持待补录/待核，成片如需先交付应明确为预览稿，不标记正式审核通过。最终摘要给出实际覆盖、已修复问题和剩余限制；不能承诺自动检查对任何素材都零漏检。

## 发布前检查

1. **语义与取舍**：核对主要结论、口播和图示；重排图保留原意，箭头表达真实关系。实操 instruction/action/result 可追溯；关键步骤、失败状态和结果不被等待压缩掩盖。补拍与主口播衔接完整，用户明确放弃的试讲段不进入正文；剪口没有截字、残句或重复无效 take。
2. **开场与正常出镜**：按 [开场与讲师出镜策略](style.md#开场与讲师出镜策略) 核对实际首帧和语义锚点。默认讲师大屏直接开场，阶段/结构总览随后，课名页随实际介绍课名出现；用户另有开场方案时以项目记录为准。不要把封面缩略图误当成必须放在成片第零秒的静音片头，也不固定某个秒数。
3. **小窗正向覆盖**：从明确的“应出镜清单”和“允许隐藏清单”检查，而非只检查隐藏段没露人。常规图示、课名页和分屏讲解按项目策略保留讲师小窗；同一 keep 序列驱动人像和口播。逐镜查看实际成片的首、中、末及恢复边界，确认没有意外消失、两个讲师或全画幅单帧闪回。让正文、总结、重点和字幕避让人物；不要为了塞小窗缩小关键内容。
4. **人物质量**：按 [人物抠像与去溢色](style.md#人物抠像与去溢色) 和 [眼镜与镜片反光](style.md#眼镜与镜片反光) 查看正常交付画幅、原尺寸边缘和代表性短动态。核对发丝、眼镜、肩线、白衣和手势的完整性、绿色污染、光晕、孔洞及闪烁。镜片修复保留本人真实眼睛、自然眨眼和镜框；不生成假眼、冻结眼区或用错时补片替代实际表情。蒙版与人像共同使用源时钟；新增出镜范围、裁切或可见区域必须从本次最终 MP4 重新检查，旧蒙版已通过不能代替新画面复审。
5. **转场与完整播片**：按 [完整播片](style.md#完整播片) 核对用户指定完整播片的全部源内容、起止及独占画面。播片与指定全屏实操不被讲师、右栏导图、课名或多余框架盖住；等比保留必要画幅。字幕如保留，应放在不遮源内容的区域。章节卡核心及声明的前后保护区隐藏讲师和字幕，首、末帧也检查；透明层不能露出底下的人物。具体长度取自项目时间轴，不能把示例章卡帧数硬套不同帧率。
6. **字幕与标注**：字幕忠于实际语音，术语、数字、否定和条件完整；英文独立词及中英混排保留必要空格。烧入字幕、SRT、字幕源文本及时间一致；章卡按策略净空。每处框线、下划线、箭头对应当前布局和讲解位置，不能沿用重排前坐标。源图没有播放器、临时截图浮层或制作标签。
7. **声音**：完成 [底噪检查与必要处理](audio-cleanup.md) 和 [本项目响度校准](audio-loudness.md)。实际 AAC 达到已配置的综合响度及真峰值目标；默认可从 −18 LUFS、±0.5 LU 和 ≤−1 dBTP 开始，发布目标覆盖优先。复核轻声、摩擦音、句尾、停顿、循环、淡化与闪避；无削波。数值不能冒充主观试听，处理后不能把已改变的原录音声明成 PCM 恒等。
8. **最终媒体**：按下面的技术与音频章节检查本次实际 MP4，完成全长音视频双轨严格解码。仅 probe、检查渲染分段或旧成片成功，均不能放行当前成片。

## 实操、图示与提示词

- **对象正确**：口播、源素材中的应用、对象和控件一致。开发工具与目标应用的同名菜单不能互相代替；区分真实动作、展开菜单、当前状态、结果回读和交互示意。不同记录或不同测试结果要标明，不能拼成一次成功过程。
- **过程充分**：按步骤检查准备、选择、输入、执行、结果和验证。宏观设计先展示所讲结果，交互说明展示对应真实操作；不把 AI 生成或开发中的等待画面泛配整段讲解。源素材充分时，不应剪掉操作入口和连续上下文。概念图或用户指定图示段可稳定停留，不能机械插入录屏。
- **画面大而稳定**：主要操作区域完整、文字可读、控件空间关系保留。缩放、框选和聚光用于实际重点，不频繁追逐鼠标或把同一桌面切成孤立碎块。
- **分屏信息完整**：按 [split-screen-layout.md](split-screen-layout.md) 核对纵向适配、只保留一层主标题、原字形/图标、关系和总结。无右侧内容的主图居中；不把横图缩成上方小缩略图、下方留大片空白，也不为了填满而删掉信息。重排后的强调位置从实际布局重新计算。
- **原文模式清楚**：可读字号下一页能容纳全文时，稳定显示完整原文，按项目策略隐藏讲师；长提示词配实操可采用右栏节选。灰字为焦点前后连续真实上下文，深字为当前重点，省略边界明确；完整可复制文本另行交付。检查首尾约束、页脚、下载提醒、划线和小窗避让；节选不标成全文。
- **动态对比真实**：左右对比使用对应版本、同类功能的实际视频，保留动作开始、反馈和必要阅读时间。不同数据不冒充同一记录，等待不冒充完成；静图推拉不冒充动态实操。时长由动作和阅读需要决定，不固定复用其他项目的对比秒数。
- **隐私检查最终像素**：先审源并跟踪精确遮罩，再从最终 MP4 查看所有实操镜头的首、中、末、遮罩切换、滚动、弹窗和缩放/变速边界。姓名、账号、邮箱、凭证及私人路径按授权范围遮盖，保留教学文字和必要上下文；图卡和小窗副本也检查。OCR 只能辅助定位，不能替代高风险区域的目视复核。

视觉检查至少覆盖每个镜头的实际成片联系表，再查看修改段、原文首尾、操作结果和隐藏/恢复边界的原尺寸帧或短段。联系表不够看文字或边缘时另提原分辨率证据。记录实际查看过的帧、范围和方法，不把已提取、已哈希或数值通过的样本写成已经人工审看，也不把有限抽验称为全课逐帧观看。

## 技术与时钟

- 从冻结时间轴读取目标尺寸、帧率、有理数时间基、总帧数、音频采样率、声道和章节。当前通用工具支持 2560×1440、60 fps、48 kHz 双声道；使用其他配置须适配并验证相应工具。逐个核对视频 PTS、DTS、帧时长和精确网格，完整解码计数与目标总帧数一致，不使用其他项目的整数常量。
- PCM 有效采样数以同一冻结时间轴为准。在当前 48 kHz / 60 fps 配置下，每视频帧为 800 个采样；其他配置须用有理数和连续整数累计处理余数，明确最终取整，不能逐段向上取整。插入、删除或补齐静音必须属于编辑记录，不能临时补零掩盖缺音。
- 检查实际 MP4 的音轨起点、采样率、声道、章节及总时长，并以遇错即退出方式完整解码音视频双轨。报告解码总帧数、实际样本数和错误，不能只看文件头或依赖容器自报的时长。
- AAC 编码预延迟和尾 padding 从 **本次文件** 的包时间戳/时长、skip/discard 信息、编辑列表和编码帧结构推导。确认解码器已应用哪些裁剪，避免重复扣除。实际有效样本必须精确等于时间轴目标；原始解码尾样本只有在元数据及当前编码结构能解释时才记为 padding。不能使用固定“最多一个 AAC 包”或 1024 样本容差，把时钟偏移、截尾或缺音判成通过。
- verify_media.py 与 project.py audit 分别辅助媒体和结构检查。TECHNICAL_PASS、STRUCTURE_PASS 只证明报告列明的方法，不能替代语义、人物、可读性、嘴型或隐私验收。工具未覆盖的有效样本裁剪、指定播片或新的布局范围要另行验证，保留待核状态直到解决。

## 音频对齐核验

1. 记录当前独立 narration、music、mixed 与最终 AAC 的内容身份。先在发布采样率和实际声道配置下核对完整采样数、有效起点及相加关系，再做降采样相关性；不能用低采样率比较隐藏数个有效采样的截尾。
2. 将实际 AAC 与当前 mixed 解码为相同的分析格式，例如 16 kHz 单声道，按实际时间零点对齐。窗口覆盖头尾、所有剪口、章节、循环、加速前后与长课中段。延迟应接近零且不随时间漂移；RMS 增益差可从 ±0.5 dB 范围开始检查，异常先查源、时钟和编码配置，不抬阈值掩盖失败。
3. 扫描全片分布及尾段，能量足够的窗口可用零延迟 Pearson 相关约 ≥0.95 作异常线索，并结合增益及短窗缺音检查。阈值按实际信号解释；高相关不能单独证明词音完整，只有少量同步窗或粗缺音扫描也会漏掉“人声丢了但 BGM 还在”的区间。
4. 额外对照源口播和编辑映射核查内容、增益、原速与嘴型。AAC 对新 mixed 的编码误差小，不等于原录音未处理。保留真实执行范围和未核实项；没有主观依据不声明全课耳机试听。

## 迭代与交付

先用代表性短段校准，再完成全课并复审实际导出文件。有实质问题就修受影响镜头或音轨，重新检查相应段和后续时间轴；通过后不为固定检查次数重复编码。说明有证据的改进和实际限制。

技术、音频、视觉、隐私报告分别记录通过、待核或待修，写明方法、实际样本、范围与局限。每份最终报告绑定本次 MP4 的绝对路径、SHA-256、文件大小、mtime、总帧数及音频时钟，并在检查前后确认身份稳定。文件替换或重新导出后，旧报告只证明旧文件；缓存须有源内容、时间轴、配置和实际像素输入身份一致的依据才复用，复用缓存不免除新成片检查。

交付包含完整 MP4、字幕 SRT、封面、章节、制作说明，以及课程所需的可复制原文、提示词和教学图形。冻结源清单、cuts/edit-map、操作锚点、时间轴、配置、素材来源和重建脚本留在项目目录。核对资料包内的成员、字节身份和可解压性，避免声明交付却缺少原文。真实人物、私有录屏及 QA 证据不进入公开 skill。

回复先给完整成片的可播放位置，说明实际尺寸、帧率、时长和本轮变更。用户提供素材的工作流不转嫁为要求用户编写 EDL 或标出全部时间点；只对无法推断的关键问题作窄澄清。源文件缺失、工具不可用或报告未完成时，不能虚构已交付。

## 用户授权后的版本与缓存清理

正常制作时先保留前版与原始素材。**仅在用户要求清理，并有明确范围时**执行删除；“交付完成”本身不授权清理课程、原片或磁盘其他内容。一次清理经验也不构成未来自动删除的许可。

1. 确认最新正式交付已完成并可打开，保存整套交付文件的 SHA-256、大小和清单，保护成片、字幕、封面、章节及随课资料。先列出明确绝对路径的删除目标，排除原始素材、当前正式交付和其他项目。
2. 检查打开文件、渲染/导出进程和正在录制的写入。不要删除仍被使用的目标；不为清理重启录制应用、改设置或运行抢占 GPU 的工作。可先继续清理已确认空闲的目标，活动目标留待关闭后处理。
3. 在删缓存前保留冻结时间轴、字幕、操作锚点、配置、脚本和必要来源记录，以及已认可的无损 narration/music/mixed、关键蒙版和生产图形。压缩留档要保存每个成员的原路径、字节数和 SHA-256，逐成员读取验证 CRC 与哈希；不能仅因 ZIP 创建成功就删唯一输入。
4. 追踪当前项目指向旧目录的文件引用和符号链接，包括图形、最终人物蒙版、音频及源时钟数据。删除前固化仍需直接使用的依赖，或验证冷归档并写明确的恢复路径/映射。冻结历史配置可保持原样，但不能把已删除旧路径描述成当前仍可直接重渲。
5. 删除只覆盖已审定清单，使用绝对路径并重新确认边界。用户提供的原始录制、课稿、导图、音乐等默认保留；删除原始素材需要用户另行明确要求。保留必要制作记录不等于保留全部可重建抽帧、试听和候选缓存。
6. 删除后重新核对正式交付及保留归档的 SHA-256、资料包完整性和原素材清单，记录实际释放空间与剩余空间。若同时存在新录制写入，说明磁盘空闲变化会受其影响，不把理论文件大小相加当成实际释放量。

清理记录写明已删哪些缓存、仍保留哪些输入以及未来如何恢复。历史 QA 报告中的截图或分段路径可作为审核当时的证据记录，但清理后不能继续宣称这些文件仍在，也不能用历史 PASS 放行未来恢复或新生成的成片。
